# 作者指南：CK3 3D 人物前置与 VRC 迁移

这份指南用于人类作者和 AI 助手共同制作候选。工程内容和运行记录留在本机；仓库承载可重复使用的工具与经验。

## 1. 确认来源与最终外观

记录模型来源、版本、许可、文件哈希、目标服装和允许的公开范围。使用独立候选，保留原模型、原 Unity 工程、原 Blender 工程、存档与正在使用的 Mod。付费/私人 Avatar 和作者能本机使用的素材不一定允许公开再分发。

非 Unity 来源先 `inspect` 原始文件。Unity/VRC 来源则先确认实际装配：启用部件、衣服开关、身体裁切、Shape Key 值、嵌套骨架、材质实例及插件。不要仅凭 FBX 里存在一个网格就认为最终 Avatar 会显示它。UnityPackage 在本工具中只是资源清单入口。

Unity BakeMesh、根变换与 bindpose 的组合可能带来 100 倍尺寸错误。逐部件比对包围盒、姿态与相对位置，而非只把整个人统一缩放。只有鞋子可见时先查隐藏部件和比例；缺手臂时查蒙皮/旋转；左右镜像时查坐标变换、法线与三角形绕序。这里提供检查经验，没有自动执行 Unity 烘焙的脚本。

## 2. 准备几何、骨架和纹理

统一最终骨架并审阅非标准骨骼。保留所有受权重骨骼、必要祖先、道具挂点与完整原版身体骨架前缀。不要以骨骼数量最少为目标。合并骨架后逐部件检查蒙皮、左右方向、负缩放、UV、法线和材质槽。

身体裁切依据服装遮罩与实际穿搭，不能凭高度包围盒盲删三角面。侧/背面、抬腿、弯腰、坐下必须检查孔洞。裙摆局部权重与髋部/大腿/裙摆链分别审阅；衣服整网格的平均权重比例不能代替裙摆质量判断。

将最终可见颜色与 alpha 准备成 CK3 可引用的贴图；纹理不在本仓库。Unity toon 材质不能直接搬进 CK3，插件参数与 CK3 PBR 参数也不能逐项照抄。先保持原始颜色，再选择人物哑光、脸部或透明效果。贴图转码/烘焙由作者另外完成，当前完整 build 复用参考 Mod 的已准备纹理，不自动烘焙任意源材质。见 [材质指南](SHADER_GUIDE.md)。

## 3. 建立头身、相机与挂点契约

全身人物采用独立不可见头部代理。头部对齐本机原版头部骨架顺序，身体保留本机原版身体骨架前缀。标准头部相机/灯光节点只在头部暴露；身体内部同名辅助节点使用人物私有名称。

`bn_h_head` / `bn_h_head_mid` 在头部，`camera_torso_look_at` 在身体。不可见代理不能重复提供 `bn_l_prop`、`bn_r_prop`、`body_root` 以免抢占道具或御座节点。joint_attachment 要分别在父对象和子对象解析到节点，不能用两份骨架的并集充当成功证据。

人物面板、理发器与宫廷的镜头不同。看见完整模型不证明所有相机都正常；不要向原版 camera/environment 注入猜测字段，也不要用全局镜头覆盖掩盖某个自定义人物的问题。

## 4. 准备动作与输出

完整流程依赖 [prepared-reference-v1](PREPARED_REFERENCE.md)。参考包必须已经包含可供该骨架使用的动作，不允许把尚未转换的原版 animation-set import 当作完成。

每段实际引用的 `.anim` 核对骨骼数量、名称、顺序、父关系、初始值、采样长度与有限数值。名称相似不代表原版动作可用于含附加头发/裙摆骨的模型。空采样节点可以存在，不能输出 `t=[]` / `q=[]` / `s=[]` 空属性。

固定体型颈骨长度保护默认按目标绑定长度检查，超过 ±15% 时只修正平移长度，保留方向、旋转、缩放与根位移，并输出 `motion_guard.json`。站姿收窄默认关闭，只是动作白名单上的试验；宽站姿、抱臂和运行时混合仍可能未解决。不能通过缩短腿骨、缩放整个人或删身体消除这些问题。

配置 `profiles.local/<id>.json` 后依次 doctor → audit → build → compile → check。`build` 生成模型包与离线预览；预览不运行 CK3 着色器。多人物通过 compile 统一合并选择器并保留原版内容。未提供的新动作会显式回退待机并记录，不等于这些动作已适配。

## 5. 安装、核验与用户测试

Runtime 是公共材质前置；models 是选中的人物组合。生成 Runtime 时从作者自己的 CK3 读取底层文件。安装在作者明确执行 install 后发生；先读生成的“测试模组位置.txt”，区分构建目录、启动器描述文件、注册路径、链接与物理资源目录。

install 返回事务目录，用 verify-install 从实际入口读回文件与哈希。旧物理版本保留，回退前核对归属与后续修改。手工模组不自动接管。用户确认播放集后完整退出游戏并重启。

用户在真实游戏测试材质、人物面板、理发器、宫廷、坐姿、武器、抱臂和转换过程，并检查原版男女/儿童回归。出现空白、绑定姿势或挂点错误须读取本次 CK3 日志。用 trace-state 对照实体状态、随机变体、动画文件和哈希，不从截图猜动作 ID。按 [检查表](ACCEPTANCE_CHECKLIST.md) 留证；自动通过与用户游戏验收分别记录。
